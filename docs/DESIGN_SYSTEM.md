# CashControl — дизайн-система (v1.1: светлая тема в коде + тёмная тема как исходная концепция)

Зафиксировано по итогам ревью дизайн-концепции в июне 2026. Источник истины для
цветов — `tailwind.config.js`, этот документ объясняет *почему* выбраны именно
эти значения и как ими пользоваться.

Хронология важна для понимания токенов: сначала была утверждена **тёмная**
концепция (графит + один синий акцент, в духе премиальных автобрендов), затем
по запросу она была **выведена в светлую тему** с тем же принципом и с
небольшим добавлением цвета (success/warning/danger). В коде сейчас реализована
только светлая тема — тёмная задокументирована ниже как источник и как спецификация
для будущей реализации (см. «Не реализовано в коде»).

## Принцип

«Сдержанный премиум»: один брендовый акцент (синий) + три статусных тона
(зелёный/янтарный/терракотовый). Никаких ярких/кислотных цветов, сплошных
цветных «героев» на весь блок, неоновых эффектов и градиентов. Ориентир —
визуальный язык премиальных автомобильных брендов (Mercedes/BMW): графит,
серебристо-серый, один сдержанный акцент — адаптированный в светлую тему.

Цвет несёт смысл, а не декор:

- **primary (синий)** — бренд и интерактивные элементы: ссылки, активные
  состояния, кнопки действия, выделение «выбранного» элемента. Не используется
  как статус.
- **success (зелёный)** — «всё хорошо»: бюджет в норме, активный пользователь,
  положительное действие.
- **warning (янтарный)** — «обратите внимание»: бюджет близок к лимиту,
  предупреждающее действие (деактивация).
- **danger (терракотовый)** — «требует внимания/деструктивно»: бюджет
  превышен, ошибка, удаление, расход (только в местах, где это уже было
  историческим поведением — см. «Нюансы» ниже).

Намеренно **нет** отдельного токена под «доход»/«расход» — это семантика
конкретного экрана (`text-primary-600` для дохода, `text-danger-500` либо
нейтральный `text-gray-500` для расхода/перевода), а не часть палитры.

### Нейтральные

Используется стандартная серая шкала Tailwind (`gray-50`…`gray-900`) без
переопределений — она уже достаточно близка к графитовой палитре концепции

бордеров и фонов карточек.

## Тёмная тема (исходная концепция)

Светлая тема — не отдельный дизайн, а инверсия тёмной с тем же принципом
«один брендовый акцент + статусные тона, без неона и градиентов». Ниже —
токены тёмной версии в той же структуре, что и светлая, для прямого
сравнения. **В коде не реализована** — нет ни `darkMode` в Tailwind, ни
переключателя темы; это спецификация на будущее.

### Поверхности и текст (графитовая шкала)

| Роль | Светлая (в коде) | Тёмная (концепция) |
|---|---|---|
| Фон страницы | `#F5F6F7` | `#1A1D20` |
| Фон карточки | `#FFFFFF` | `#23272B` |
| Фон вложенного элемента (пилюли, инпуты) | `#F0F1F2` | `#2D3236` |
| Бордер | `#E2E4E6` (≈ `gray-200`) | `#3A3F44` |
| Текст основной | `#1A1D20` (≈ `gray-900`) | `#ECEEEF` |
| Текст вторичный | `#6B7177` (≈ `gray-500`) | `#A4AAAE` |
| Текст приглушённый | `#9398A0` (≈ `gray-400`) | `#7B8186` |

### Primary — синий (бренд, интеракция)

| Роль | Светлая | Тёмная |
|---|---|---|
| Подложка/фон акцентного элемента | `primary-50` `#E3EEF2` | `#27414D` |
| Насыщенный акцент (кнопки, подчёркивания, фокус) | `primary-500` `#3D8BB0` | `#3B82A6` |
| Текст-акцент на нейтральном фоне | `primary-600` `#2D7093` | `#3B82A6` |

В тёмной теме акцент берётся ярче/светлее (`#3B82A6` против `#2D7093` на
свету) — на графитовом фоне более тёмный синий терял бы контраст и
читаемость.

### Success / Warning / Danger — статусные тона

| Статус | Светлая (500/600) | Тёмная (акцент / фон-подложка) |
|---|---|---|
| Success (норма) | `#6B8F71` / `#5C8C63` | `#7BA382` / фон `#1F2E22` |
| Warning (близко к лимиту) | `#C98A3E` / `#B8853D` | `#C98A3E` / фон `#3A2F22` |
| Danger (превышено/ошибка) | `#C2685F` / `#B5604F` | `#C2685F` / фон `#3A2426` |

Логика подложек в тёмной теме обратная светлой: на свету самый светлый stop
(`50`) — это фон, а самый тёмный (`700`) — текст; на графите наоборот —
приглушённый тёмный оттенок (`*_BG` выше) идёт под иконку/бейдж, а сам
насыщенный цвет — как акцентный текст/заливка прогресс-бара поверх него.

### Решения, перенесённые из тёмной темы в светлую без изменений

- Один брендовый акцент на интерактивные элементы, статусы — отдельные тона.
- Никаких сплошных цветных «героев», градиентов, теней, неона.
- Кольцевые (ring) индикаторы для целей вместо обычных progress-bar —
  присутствовали в обеих версиях концепции одинаково.

## Типографика

- Шрифт: системный sans (Tailwind default, без переопределений).
- Заголовки страниц: `text-2xl font-bold text-gray-900`.
- Крупное число баланса: `text-4xl font-semibold text-gray-900` (не `font-bold`
  — премиальные интерфейсы используют чуть более лёгкий вес даже на крупном
  кегле).
- Вторичный текст/подписи: `text-sm text-gray-400` / `text-xs text-gray-400`.

## Радиусы и поверхности

- Карточки: `rounded-2xl border border-gray-200 bg-white`, без теней (тени не
  используются вообще — только бордер).
- Поля ввода/кнопки/пилюли: `rounded-xl` или `rounded-lg`.
- Бейджи/чипы статуса: `rounded-full`.

## Ключевое структурное решение: без цветных «героев»

Раньше баланс на дашборде показывался в сплошном цветном градиентном блоке
(`bg-gradient-to-br from-primary-500 to-primary-700`). По утверждённой
концепции это убрано: баланс — крупная цифра на белом фоне с тонким
акцентным подчёркиванием (`w-7 h-[3px] bg-primary-500`) под ним. Если
где-то в новых экранах появляется идея «залить карточку цветом» — это
противоречит принятому направлению, нужно сначала свериться с этим
документом.

## Нюансы и осознанные исключения

- **LandingPage.jsx** не мигрирован — это маркетинговая страница со своим
  оформлением (яркий синий `blue-600`, blur/glow-эффекты на хиро), и эти
  приёмы прямо противоречат принципу «без неона и градиентов» из основного
  приложения. Решение, приводить ли лендинг к единой палитре или оставить
  ему отдельный маркетинговый язык — открытый вопрос, не закрывали его
  самостоятельно.
- **Бейдж роли admin/user** (`bg-purple-100 text-purple-700` в админке)
  оставлен как есть — это не финансовый статус, а служебная метка роли,
  не входящая в обсуждённую палитру.
- Цвет «расход» в списках операций местами `text-danger-500`, местами
  нейтральный `text-gray-500` (так в `EditTransactionModal` для типа
  «перевод», который не доход и не расход) — это осознанная семантика
  конкретного места, а не часть токенов.

## Следующий шаг (не реализовано в коде)

Утверждённая визуальная концепция включает элементы, которых пока нет в
текущей кодовой базе — это следующий слой работы, не затронутый этим
обновлением палитры:

- Кольцевые (ring) индикаторы для целей/«банок» вместо обычных progress-bar.
- Карточка «семейная банка» с общим доступом и стеком аватаров участников
  (требует фичи family-sharing на бэкенде — см. приоритизированный бэклог,
  пункт P0).
- Bottom-sheet модалка добавления операции с укрупнённым вводом суммы
  вместо текущей формы с выпадающими списками.
- **Тёмная тема целиком** — токены задокументированы выше, но в коде нет ни
  `darkMode` в `tailwind.config.js`, ни CSS-переменных для переключения
  поверхностей, ни UI-переключателя. Технически правильный путь — не
  `dark:`-классы на каждый элемент (это означало бы повторно пройтись по
  всем уже изменённым файлам), а CSS custom properties для
  фон/текст/бордер-ролей, которые подменяются по классу `.dark` на корневом
  элементе; `primary/success/warning/danger` тогда тоже переезжают на
  переменные с разными значениями для светлой/тёмной темы.
